# v0.1.1: Registro de Componentes

**Etapa:** 2 (Sinais do Core) | **Status:** não iniciada | **Depende de:** v0.0.3

## Objetivo

Cadastrar os componentes que nascem do design e fazer o editor se adaptar a eles.

## Entrega

- Definição de componente: id, nome, versão, schema de props (campos tipados, obrigatoriedade, valores padrão) e variações
- **Estilo por nome, nunca CSS:** variações e estilos são declarados como tokens (por exemplo, destaque-grande); o Core traduz o token em apresentação
- Props de apresentação opcionais, como o estilo de data do componente (relativa, extensa, curta), sempre sobre data crua
- Editor orientado a schema: um componente novo com props simples ganha formulário e bloco automaticamente
- Ponto de extensão para editor customizado: o programador registra uma interface própria quando o schema não basta
- Catálogo no painel (componentes, versões e onde são usados) e validação das props ao salvar

## Sinal ao Core

Definições de componentes (id, versão, schema e tokens de estilo) publicadas.

## Pronto quando (critério de aceite)

Um componente novo, registrado por código ou arquivo de definição, aparece no editor sem alterar o núcleo do CMS.

Cada critério vira teste de aceite em `tests/`.
